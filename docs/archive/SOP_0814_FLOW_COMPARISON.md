## 当前运行边界

1. **列表初筛 + 详情复筛已支持**：正式筛查使用 `--with-detail --require-detail`；列表层先判定，详情指标再复判，申请商品必须是主推款。
2. **只读 API 已用于列表和详情**：日常只读和正式批准都可用 `--data-source auto`，API 异常会回退 DOM；写来源由 `--write-source dom|api` 显式选择，默认 API。
3. **批准后飞书写入已支持但不默认执行**：需同时满足批准状态确认和 `--write-feishu`；目标为「达人关系管理(新)」。
4. **第 6 步和第 7–9 步是独立脚本**：四个常用脚本断开，批准结束后不会自动发介绍私信；第 7 步也不会自动触发物流回写和物流私信。指定已批准达人发第 6 步时用 `--creator-id` / `--creator-name`，不要用 `--from-export --max-rows N` 代替。
5. **第 9 步使用 TikTok 物流单号**：`main_order_id` 只填飞书「订单号」，商家订单页的「TikTok 物流」单号才是飞书「快递单号」和发给达人的号码。

## 本次飞书字段规则

### 新建达人关系记录

写入「达人关系管理(新)」：

```text
红人ID       = TikTok 达人 handle
人员         = 王良希（技术）
寄样产品     = 主推表货号映射后的现有单选项
履约率       = 列表履约率，缺失时可使用详情预计发布率
粉丝数       = 页面原始值
合作状态     = 待发货
是否已寄样   = 不勾选
```

去重键仍为：`红人ID + 寄样产品`。

### 填写物流后的联动

```text
订单号       = 样品申请已发货记录的 main_order_id
快递单号     = 商家订单页「TikTok 物流」单号
是否已寄样   = 勾选
合作状态     = 待发货 -> 待发布
```

保护规则：

1. 没有物流单号时，不勾选寄样、不推进合作状态；
2. 飞书已有同一物流单号时，允许幂等补齐「待发布」；
3. 飞书已有不同物流单号且未传 `--overwrite` 时，不覆盖单号，也不推进状态；
4. 当前状态是「已发布」等后续状态时，只补物流字段，不把状态回退成「待发布」；
5. 飞书没有匹配记录时不新建物流记录，留给人工核对。
